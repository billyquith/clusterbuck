What the columns mean

Ability scores — how well, per kind of job

Each model is measured on four kinds of job, scored 1–10 by running a fixed suite of short test prompts through the node as ordinary jobs. A job asking for task_class + min_ability is routed only to a model that clears that bar in that class — the four are never averaged.

Reading a score

the scale
Anchored, not relative: roughly 9–10 frontier cloud, 7 a strong 70B-class local model, 5 a good 8B at Q4, 3 a 3B, 1 sub-1B or broken. Versioned (currently {{ scale }}) so an old score is never compared with a new one.
{{ "%g"|format(ceiling) }} is the ceiling
The checks are mechanical — right field, right number, within the limit — so they prove compliance, not quality. A perfect pass maps to {{ "%g"|format(ceiling) }}, meaning “passed everything the checker can verify”. Anything above {{ "%g"|format(ceiling) }} did not come from this checker — it was written by an operator (judged evaluation is designed, not built).
7/10
Suite items passed out of those scored — the evidence behind the number.
seed
A placeholder that shipped in the code, not a measurement. The model is queued to be measured.
—
Not measured yet. Need-shaped routing cannot select it for that class.

The other columns

serves
The capability tiers that name this model — the address a client sends a job to. A tier name such as 8b-extract is a terse label a person chose; nothing reads meaning into it, and a tier is not limited to the class in its name. The line under it is the tier's description from fleet.yaml, and is what the tier is for. The scores are what say what the model is actually good at.
tools
Supports tool / function calling.
json
The runtime can constrain output to a JSON schema. This is about the form of the output; the extract score is about getting the content right.
vision
Accepts images as input.
no pill
Not declared in the model catalog — which may mean “no” or just “not curated”. Either way, a job that requires the feature skips this model until the catalog says it has it.
footprint
Download size, parameter count and quantisation, and the context window (how many tokens of input plus output it can hold at once).
tok/s
Median output tokens per second, measured on that node from real jobs.
warm / installed
Warm is loaded in memory and answers immediately; installed is on disk and pays a load first.
